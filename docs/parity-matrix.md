# Frontend/backend parity audit

Audit source: `docs/backend-blueprint.md` v1.1, especially Sections 5, 8, 15, 17, 18.3–18.11 and
Appendix E; the frontend typed client, mock API and routes; shared contracts; and backend controllers,
schemas, permissions, rate limits and tests. Status is evidence-based. An Appendix E row is not
`done` until its parity Playwright spec passes in mock mode and against the real local backend.

## Inventory notes

- The supplied 1.1 blueprint is now installed at `docs/backend-blueprint.md`. Its endpoint table
  states about 210 endpoints; the gateway currently implements 14 HTTP routes: health/readiness/
  metrics, config, development dummy health, and nine reaction/reaction-stream routes.
- All backend service packages other than `gateway` contain only their package/readme/index
  scaffolding. Application migrations are absent apart from kernel/outbox and reaction tables.
  `infra/docker/docker-compose.yml` starts Postgres and Redis only; it does not start the gateway
  or a backend service stack.
- Existing backend validation consists of kernel config/cursor/rate-limit schemas/helpers and the
  new shared reaction, mention and unread schemas. Reaction controllers validate request paths,
  queries, response pages and stream events. The mock/client/controller share these schemas for the
  covered shapes. Most endpoint contracts remain TypeScript-only or absent.
- Reaction authorization and rate limits exist in `ReactionsService`: asset A:post for writes,
  A:read for users, participant/no-block for DMs, C:mod for clear; write/burst/users limiter
  families. Gateway service and security tests exist, but there is no parity contract fixture that
  calls a mock and a real endpoint.
- `NEXT_PUBLIC_USE_MOCK` is the only frontend mock selector; the blueprint's `USE_MOCK_*` feature
  flags are not implemented. Shared constants found: `ALLOW_CUSTOM_ASSETS=false`,
  `ADD_ASSET_ROLES`, `QUICK_REACTIONS`, `MAX_DISTINCT_REACTIONS_PER_MESSAGE=20`, and
  `MAX_REACTIONS_PER_USER_PER_MESSAGE=10`. No `MAX_MENTIONS` or frontend `ENABLE_TYPING` flag was
  found. `PROFILE_TABS` is local to the profile view. Backend `ENABLE_TYPING` is a config flag.
- No `frontend/e2e/parity/` directory/specs exist. Existing feature specs do not establish both
  mock and real-backend parity. No mock flag was disabled.
- `mockApi` implements the typed `ApiClient` surface. The per-row call inventory below names those
  mock handlers; direct local session and stream routes are called outside the typed client.
- Contract match values follow the requested vocabulary: `yes`, `shape differs`, `path differs`,
  `missing`. A backend endpoint that does not exist is `missing`, even if the blueprint has a target
  shape.

## Initial parity result and gap order

- Appendix E: **0/34 done and matching (0%)**. No row has the required two-mode parity spec.
- Backend status: **4 partial rows** (4 bootstrap/config, 16 reactions, 18 realtime, 34 deployment—each is partial at the feature level); remaining product rows are missing. No feature flag was switched off.
- Contract order: finish shared request/response schemas and fixtures, including explicit path/body differences listed above; then implement missing endpoints in Section 17 order (Phases 1–7); then fix frontend behavior mismatches and add the parity specs. This matrix records the already implemented reaction/mention schema slice, not a completed contract migration.
- Known behavior gaps to verify/fix at the behavior stage: mock reactions are fabricated by a timer; existing-user login still has a profile-completeness setup decision; front-end data and contracts include DOB; unread, default asset, mention row and badge states must be tested against v1.1.
- Behavior fixes in this pass: mock reaction subscriptions no longer synthesize reaction events; existing-account login no longer redirects to setup based on `profileComplete`; the shared catalog is restricted to Appendix A and uses `rules`/`events`/`campaigns` kinds.
- Keep all features on mock mode until their own parity spec passes in both modes. Report any remaining Appendix E row as incomplete.
